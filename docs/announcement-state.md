# Announcement state (SIG-107)

The feed's detail controls save/unsave, mark handled/undo, and snooze for one hour. Snoozed announcements leave the active feed and can be restored from the Snoozed announcements disclosure. A one-second clock check brings them back when the saved instant is reached; reload also recalculates visibility. Original message data and provider read state are untouched.

The repository has no campus account session/authentication integration yet. Development and tests therefore use an explicitly labeled local demo sign-in with two synthetic profiles. Sign-in creates a signed eight-hour HttpOnly, SameSite=strict cookie. The state API resolves the user from that cookie, never from a query/body user ID. Cross-origin mutations are rejected. Demo login and state access are disabled in production. Real account integration must replace the session resolver before production use; demo identities are not verified university identities. The signing key is process-local; restarting the server requires signing in again.

State persists across page reloads/server restarts in ignored .signal-mock/announcement-state files, partitioned by the resolved user. These files contain flags, IDs, snooze times and versions, never email contents or credentials. The local single-process repository serializes atomic writes and rejects stale versions with 409. Distributed deployments require a database with conditional writes. Storage failures return stable safe errors. A failed optimistic update restores the previous state for that item while preserving independent updates; an in-flight item is disabled to prevent overlapping writes. Reload after a version conflict to obtain current server state.

The API requires a real session or explicit demo sign-in. Anonymous browsing remains possible, but state controls are disabled. Switching demo profiles reloads the page so state from one identity never carries into another. Demo sign-in is a development convenience; anyone using the same local server can choose either synthetic profile.

Validation: repository persistence/isolation, concurrent writes, stale versions, malformed patches, exact snooze expiry, optimistic rollback, signed session tampering/expiry, API session scoping, origin checks and production denial are covered by unit/API tests. Visual evidence is attached to the PR. All data is synthetic.

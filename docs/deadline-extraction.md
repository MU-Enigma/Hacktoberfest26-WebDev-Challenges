# Deadline and action extraction (SIG-106)

Call `extractMailActions(normalizedMessage, { timeZone })`. The default is APP_TIME_ZONE. The result contains deadlines, actions, and stable warnings; original message content is never changed. Each result records its source field and exact UTF-16 text range (end exclusive). A future announcement adapter can attach result.actions to the shared Announcement contract and show result.deadlines beside the source text. Invalid receipt timestamps or timezone settings return warnings and empty results, so callers can still display the announcement.

Supported date expressions: ISO calendar dates, Indian day/month/year dates using slashes, dots or hyphens, day plus English month name and optional year, today/tomorrow, in N days, and weekday references. Time can use 24-hour or AM/PM notation, optionally IST, UTC or GMT. Relative dates anchor to receipt time in the configured timezone, making replay deterministic across midnight and year boundaries.

A missing year uses the receipt year as a tentative interpretation and requires confirmation. Numeric dates that also admit a different month/day interpretation have no resolved instant. Dates without a time never acquire an invented end-of-day deadline. Weekday references require confirmation; `next` selects the next occurrence, including seven days later when receipt day matches. Invalid dates, DST gaps and repeated DST times also require confirmation. Multiple dates in an action's segment remain unassociated rather than selecting one silently. English keyword/regex extraction is deliberately bounded; other expressions may remain solely in the original message.

Only segments with action or deadline cues produce date candidates, reducing incidental date matches. Common action verbs include submit, register, complete, apply, pay, upload, attend, confirm, fill, send and respond. Action-only text remains useful without a deadline. Date candidates in the subject are not automatically assigned to actions in the body: that relationship needs user confirmation or future contextual matching.

After confirmation, `extractedDeadlineInfo(candidate, now, timeZone)` delegates display and exact instant comparisons to SIG-003's getDeadlineInfo. Supply an explicit now shared by all rendered records. Tentative dates return no deadline state until confirmed. UI confirmation controls and persistence belong to the consuming interface; this PR provides extraction and utility integration.

Tests use synthetic mailbox records and fixed receipt times. They cover Indian numeric ambiguity, invalid dates, missing years/times, leap days, year rollover, local midnight, explicit UTC, DST ambiguity, source offsets, multiple dates, action-only notices, graceful failures and SIG-003's exact overdue boundary.
